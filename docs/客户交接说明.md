## 1. 交付概述

**terminal-insight-v2** 是证据优先的智能终端（手机 / 手表 / 眼镜）调研流水线：

```text
采集(collect) → 抽取(extract) → 补链(backfill) → 校验(verify) → Excel → Vote
```

核心承诺：

- 非空字段可追溯到原始网页快照与 URL  
- 多信源冲突默认并列，不静默压平  
- 新品类原则上只加一个 Excel 模板，不改业务代码  
- 提供本地桌面 GUI，便于配置、跑批与查看产物  

**当前实现边界（务必对齐预期）**

| 能力 | 状态 |
|------|------|
| Collect / Extract / Backfill / Verify / Excel | MVP 可用 |
| 定向采集 | **已实现**（GUI）：粘贴「品牌 + 型号」跳过窗口发现，写入 `targets.json` |
| Vote（评审投票） | **已实现**：六参考系并行提名 + 四受众审阅，写出 `votes.json` 并回填 Excel「亮点投票」「受众视角」 |
| Gold 人工审核发布 / 链接闸门 / Chat | **未纳入 GUI MVP** |
| 流水线中途停止 | **不支持**（需等当前任务跑完；关掉 GUI 窗口会中断） |

## 4. 模型与搜索等配置

配置来源优先级：GUI「配置」保存写入 **exe/项目根目录 `.env`** → 进程内生效。密钥**不会**打进安装包。

### 4.1 必填 / 强烈建议

| 变量 | 作用 | 说明 |
|------|------|------|
| `OPENAI_API_KEY` | LLM 抽取 / 结构化 | OpenAI 兼容接口密钥 |
| `OPENAI_BASE_URL` | API 地址 | 默认 `https://api.deepseek.com/v1` |
| `OPENAI_MODEL` | 模型名 | 默认 `deepseek-v4-pro` |
| `DOUBAO_API_KEY` | 豆包网页搜索 | Discover / 补链检索；`DISCOVERY_BACKEND=auto|doubao` 时需要 |
| `TAVILY_API_KEY` | Tavily 搜索 | `DISCOVERY_BACKEND=tavily` 或 auto 降级时使用 |

### 4.2 调研窗口与品类

| 变量 | 说明 | 示例 |
|------|------|------|
| `CATEGORY` | 品类 ID，对应 `category_templates/{id}.xlsx` | `phone` / `watch` / `glasses` |
| `DATE_START` / `DATE_END` | 发布日期窗口（含起止） | `2026-01-01` ~ `2026-07-31` |
| `REPORT_MODE` | `research`（研究）或 `gold`（对外更严） | 默认 `research` |

### 4.3 并发与质量旋钮

| 变量 | 默认 | 含义 |
|------|------|------|
| `COLLECT_MAX_WORKERS` | 4 | 采集并发 |
| `COLLECT_FETCH_WORKERS` | 4 | 抓取并发 |
| `COLLECT_MAX_URLS_PER_DEVICE` | 8 | 每机最多抓取 URL 数 |
| `EXTRACT_MAX_WORKERS` | 4 | 抽取并发 |
| `EXTRACT_TARGET_SOURCES` | 10 | 每机目标信源数（软目标） |
| `BACKFILL_MAX_ROUNDS` | 3 | 补链轮次上限 |
| `DISCOVERY_BACKEND` | `auto` | `auto` / `doubao` / `tavily` |
| `JINA_READER_ENABLED` | `true` | HTTP 失败时是否用 Jina Reader 降级 |
| `FETCH_MIN_BODY_LEN` | 300 | 正文过短视为无效 |
| `HTTP_TIMEOUT` / `OPENAI_TIMEOUT` / `DOUBAO_TIMEOUT` | 见 `.env.example` | 超时 |

完整清单见仓库 [`.env.example`](../.env.example)。

### 4.4 配置操作（GUI）

1. 启动后点右上角 **⚙ 配置**  
2. 填写模型、Base URL、API Key、检索后端与密钥  
3. 设置品类与日期窗口、并发  
4. 点 **保存**（合并写入 `.env`，不会清空未展示的键）

## 5. 具体操作流程

### 5.1 客户侧：打包 GUI（推荐）

1. **安装 WebView2**（Win10 如无法打开窗口时优先检查）  
2. 解压交付文件夹到本地路径（路径避免无权限目录；中文路径一般可用，仍建议简短英文路径）  
3. 双击 `terminal-insight-v2.exe`  
4. **首次**：打开配置，填入 Key，选品类与日期，保存  
5. 顶栏选择 **窗口发现**（普查）或 **定向机型**（粘贴品牌+型号 → 解析预览 → 确认）  
6. 点 **全部运行**，或点击某一阶段「从该阶段跑到结束」  
7. 运行中阶段卡片会随完成翻绿（含 `partial`）；结束后在 **覆盖率** 查看缺字段  
8. 用 **📋 Excel / 🔗 信源 / 打开目录** 查看产物（Excel 含「亮点投票」「受众视角」）  
9. 历史批次在 **Runs** 中点击切换；可用 **Resume 当前 run** 在已有批次上继续  

**产物位置**（exe 同级）：

```text
data/runs/{category}_{start}-{end}_{timestamp}/
  sources.html / sources_*.html
  targets.json                    ← 仅定向采集
  votes.json                      ← Vote 原文（六票 + 四受众审阅）
  collection_manifest.json
  assertions.jsonl
  coverage_report.json / review_queue.json / resolved.json
  *.xlsx                          ← 参数 Excel（含「亮点投票」「受众视角」）
  steps.json / run.json
data/memory/
  facts.db                        ← 事实库
  blobs/                          ← 内容寻址原文
  llm-wiki/raw/…                  ← 按设备/来源组织的快照视图
```

### 5.2 研发侧：源码 CLI

```bash
cd terminal-insight-v2
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev,gui]"
cp .env.example .env          # 编辑填入密钥
python -m terminal_insight_v2.cli init

# 编译品类（新增模板后）
python -m terminal_insight_v2.cli category compile --template category_templates/phone.xlsx

# 跑流水线（CLI 目前只走窗口发现）
python -m terminal_insight_v2.cli run \
  --category watch --start 2026-01-01 --end 2026-07-31 \
  --stages collect,extract,backfill,verify,excel,vote

# GUI（定向机型请在窗口里操作）
python run_gui.py
```

### 5.3 新增品类（业务扩展）

1. 按 [CATEGORY_TEMPLATE_SPEC.md](./CATEGORY_TEMPLATE_SPEC.md) 制作 `{category_id}.xlsx`  
2. 放入 `category_templates/`（源码）或 exe 旁同名目录（覆盖/新增）  
3. 执行 `category compile` 或直接在 GUI 切换品类后运行（会加载编译）  
4. **无需改 Python**；模板不完整应编译失败，勿跳过  

### 5.4 建议业务节奏

1. 先小窗口或 **定向 2–3 机** 试跑，核对 `sources.html` 机型是否串号  
2. 再全量 collect → extract → backfill → verify → excel → vote  
3. 用覆盖率与 `review_queue.json` 做人审补链决策  
4. 打开 Excel「亮点投票」看六套取景框提名，「受众视角」看谁该关注（非 Q2 长文，受众结论不是新事实）  
5. 对外发布时改用 `REPORT_MODE=gold`（更严格留空策略），并走人工 Gold 流程（当前 GUI 未完整覆盖，需按架构文档 / 后续版本）

## 6. 部署与运行注意事项

### 6.1 安全

- **API Key 仅放客户本机 `.env`**，不要提交 Git、不要随邮件明文群发完整包内密钥  
- 交付前检查打包目录中**无**生产 `.env` / `data/`  
- 原始网页可能含版权内容，注意内部分发范围  

### 6.2 稳定性与限流

- 豆包 / LLM / 目标站点均有限流；并发旋钮过大易导致失败或封禁，建议从默认值起步  
- 整批「全部运行」耗时长（可达数十分钟～数小时），**不要中途强杀**（当前无优雅取消，强杀可能导致半成品 run）  
- 失败后可对同一 `run_id` 使用 Resume，或从失败阶段重跑  

### 6.3 磁盘与备份

- `data/memory/blobs` 与 `llm-wiki/raw` 体积增长快，定期备份 `data/`  
- 不要手工改 `facts.db` 结构；升级以官方迁移为准  

### 6.4 打包交付检查清单（实施方）

- [ ] 在 **Windows** 上完成 `pyinstaller build.spec`  
- [ ] 整个 `dist/terminal-insight-v2/` 可双击启动  
- [ ] `_internal/category_templates/` 含 phone/watch/glasses  
- [ ] 包内无真实 `.env`、无客户敏感 `data/`  
- [ ] 附上本交接说明与 WebView2 说明  
- [ ] 用测试 Key 跑通「配置保存 → 短窗口 collect」冒烟  

### 6.5 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 双击无窗口 | 缺 WebView2 / 杀软拦截 | 安装 WebView2；加信任；必要时用 console 版重打排查 |
| 报错 `Failed to resolve Python.Runtime.Loader.Initialize` | 压缩包/网盘下载被 Windows「锁定」 | 右键 zip → 属性 → **解除锁定** 后再解压；或在目录运行 `unblock-windows.bat`，再启动 exe |
| 配置保存无效 | 目录无写权限 | 移到用户可写目录（如 `Documents`） |
| 采集为空 / 搜索失败 | Key 错误、网络、后端选错；或定向清单未确认 | 窗口发现查 `DOUBAO_*` / `TAVILY_*`；定向须先解析并确认 |
| 抽取大量空字段 | 模型不可用、正文过短、机型不匹配被跳过 | 查 `OPENAI_*`；看 `sources.html` 与 extract metrics |
| Excel 打不开 | 尚未跑到 excel 阶段 | 先 verify 再 excel；看 Runs 状态 |
| 阶段卡片不翻绿 | 旧版要等整批结束才刷新 | 使用含进度修复的版本（`3be2bc5` 及之后） |
| 亮点投票为空 / Vote 失败 | 未跑 vote、缺 `resolved.json`、或缺 API Key | 先跑 verify/excel；配置 `OPENAI_API_KEY` 后单独重跑 vote |
| 中文路径异常 | 偶发环境问题 | 换短英文路径重试 |

### 6.6 已知限制（交接对齐）

1. Vote 不做完整 Q2 风格长文汇总（docx/md），产出 `votes.json` 与 Excel「亮点投票」（参考系 / 取景框 / 热点 / 品牌 / 机型 / 说明）以及「受众视角」（受众 / 参考系 / 热点 / 品牌 / 机型 / 相关度 / 为什么关注 / 行动启示 / 风险与证据边界）。受众审阅是决策视角，不是新事实。  
2. 定向采集目前仅 GUI；CLI `run` 仍走窗口发现。  
3. GUI 不含 V1 级「链接确认闸门 / Memory Gold / Chat」。  
4. 不支持运行中取消。  
5. 浏览器级动态页完整渲染能力有限，依赖 HTTP + Jina 等降级链；失败会留痕而非伪造 HTML。  
6. README 中部分「下一步」表述可能滞后，**以本表与代码阶段注册为准**。
